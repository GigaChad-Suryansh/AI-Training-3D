A guide for curious people

How does a robot teach itself?

Nobody tells the robot where the beacon is. It tries things, gets a score for each move, and slowly works out what is worth doing. This page explains how, step by step, with small experiments you can run yourself. No math background needed.

1. The idea: learn from scores

Think about the game of hot and cold. You search for a hidden object, and a friend says "warmer" or "colder". You never get told the answer, but the feedback adds up and you find it.

The robot works the same way. After every move it gets a number, called a reward. Good things give points and bad things take them away. Its only goal is to collect as many points as it can over a whole attempt. Learning like this, by trial, feedback and memory, is called reinforcement learning.

That loop runs thousands of times. Early on the moves are guesses. Later they are informed.

2. Its world: places, moves and points

To keep things simple the robot sees very little. It only knows which tile it is standing on (and, in the key level, whether it holds the key). It does not see walls, pits or the beacon from afar. Each turn it can choose one of four moves: up, right, down or left.

The scores come from the sliders in the lab. These are the defaults:

What happensPointsWhy
Reaches the beacon+10The whole point of the game
Picks up the key+3A small thank-you for a useful step
Falls into a pit−10Ends the attempt, so it is a big mistake
Bumps a wall or locked door−0.5A small sting for a wasted move
Every step it takes−0.05Makes shorter routes score higher

Notice that the robot is never told "go right here". The scores describe what is good and bad, and it has to figure out the actions itself. That is why changing the sliders in the lab changes how the robot behaves.

3. Its memory: a table of notes

The robot's brain is a big table. There is one row for every tile it can stand on, and four numbers in each row, one for each move. Each number answers a simple question:

"If I am on this tile and make this move, how many points do I expect to collect from now until the end?"

This table is called a Q-table (Q stands for quality). When you turn on Show What It Learned in the lab, the floor glows brighter on tiles where the best move in the table has a high expected score.

At the start, every number is the same small, hopeful value. That is deliberate. Because nothing has been tried yet, every move looks equally promising, so the robot is curious about all of them. Once a move disappoints it, its number drops and the robot tries something else. This is a trick called optimistic starting values.

4. The learning step: nudge the note toward the truth

After each move, the robot has just learned something. It then adjusts one number in its table. The recipe is:

new note=old note+learning rate×(what I just saw − what I expected)

"What I just saw" is the reward it received, plus the best it thinks it can do from the tile it lands on, shrunk a little because that future is less certain. That shrinking number is called the discount. It is set to 0.97 here, so a point one step away is worth almost as much as a point now, but a point ten steps away is worth a bit less.

The learning rate (0.2 here) decides how far the note moves. A big rate learns fast but jumps around. A small rate is steady but slow. With 0.2, each experience moves the note one fifth of the way toward the new evidence.

If you like a tiny worked example: the robot expects 1.0 from a tile, steps onto a pit and gets −10. The gap is −11. One fifth of that is −2.2, so its note drops from 1.0 to −1.2. One bad experience was enough to make it wary, and repeating it would make the note even lower.

The first attempt is nearly random. The first time it reaches the beacon, only the tile right next to it learns that stepping onto the beacon is great. On the next attempt, the tile before that learns that stepping onto a great tile is good, and so on. The knowledge spreads backwards along the route. Wandering up or down in this corridor just bumps the wall, and you will see the robot learn to avoid that too.

6. Trying new things versus using what it knows

Imagine you always eat at the first restaurant you liked. You might never discover a better one. But if you only ever try new places, you never enjoy your favorite. Learners face the same tradeoff, called explore versus exploit.

The robot handles it with a dial called epsilon. On each move, with probability epsilon it ignores its notes and picks a random direction. Otherwise it takes the best move it knows. The dial starts at 20% and shrinks with every attempt, but never below 3%, so it stays a little curious forever.

This is why, in the lab, early attempts look chaotic and later ones look confident, with the occasional surprising detour that keeps it honest. It also explains why a robot that has mastered a level can still wobble if you suddenly change the rewards: the lab bumps its curiosity back up so it can re-test its old habits.

7. Mistakes are the lesson, and how we know it is done

Falling in a pit is not a bug. It is how the robot discovers that tile is dangerous. After one fall, that tile's note drops hard and the robot stays away. Hitting a wall teaches the same lesson in a gentler way.

The lab calls a level mastered when the robot reaches the beacon in at least 9 of its last 10 attempts, and its routes are no longer than one and a half times the shortest possible route. The shortest possible route is found separately by a plain search, which is the dashed line on the chart.

The key level is harder because the robot has to track a second fact: whether it holds the key. The same tile means something different before and after the key, so its table needs separate notes for each case. That is why this level takes longer.

When you add more robots, each one has its own table and starts from zero. They never share notes. The race you see is the same recipe run several times, with different luck.

8. What this does not do, and where to go next

  • It cannot generalize. A table only knows the tiles it has visited. Give it a new maze and it starts over. Modern systems replace the table with a neural network, which can guess about places it has never seen.
  • It works because the world is tiny. The table has a few hundred rows. A game like chess or a real street would need far more than a table can hold.
  • It is not being clever. It is arithmetic repeated many times. The surprising part is how well simple arithmetic plus trial and error can work.

Good places to keep going

  • The Nature of Code by Daniel Shiffman is a free, friendly book about simulating natural behavior in code. It is a great companion for the ideas behind this page, including neural networks and learning by evolution, where creatures improve by trial and selection instead of a table.
  • Reinforcement Learning: An Introduction by Sutton and Barto is the classic free textbook. Q-learning, the method used here, is one of its core ideas.

Words you may have seen

Reward
The score the world gives after a move.
Q-table
The robot's notebook of expected scores, one per tile and move.
Learning rate
How far each experience moves a note.
Discount
How much a future point is worth compared with one right now.
Epsilon
The chance of trying a random move instead of the best known one.
Episode
One full attempt, from the start tile to the end.
